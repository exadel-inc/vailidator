# HTML Validation Server

An HTTP server that audits submitted HTML for SEO, accessibility, and custom validation rules. It runs Lighthouse against the markup, sends the Lighthouse findings and rules to an OpenAI-compatible language model, and returns a self-contained HTML report.

## Requirements

- Node.js 20 or newer
- npm
- A Chromium-compatible browser environment for Puppeteer
- An OpenAI-compatible chat completions endpoint, such as LM Studio, Ollama, llama.cpp, or a hosted provider

Puppeteer downloads a compatible browser during dependency installation unless it is already available in the local cache. In restricted environments, make sure Chrome or Chromium is available and Puppeteer can launch it.

## Installation

```bash
npm install
cp .env.example .env
```

Edit `.env` with the LLM endpoint and model you want to use.

## Configuration

| Variable | Default | Description |
| --- | --- | --- |
| `PORT` | `3000` | Port used by the HTTP server |
| `ENVIRONMENT` | `development` | When set to `development`, failed Lighthouse audits are also written to `reports/` |
| `LLM_BASE_URL` | `http://localhost:1234/v1` | Base URL for an OpenAI-compatible API |
| `LLM_API_KEY` | `local` | API key sent to the LLM provider |
| `LLM_MODEL` | `model-name` | Model name passed to the chat completions API |

The `.env` file is ignored by Git. Do not commit API keys or other credentials.

## Running

Start the development server with automatic reloads:

```bash
npm run dev
```

Build the TypeScript source:

```bash
npm run build
```

Run the compiled server:

```bash
npm start
```

Run ESLint:

```bash
npm run lint
```

The server listens at `http://localhost:3000` by default.

## API

### `POST /audit`

Submit an HTML document and one or more plain-text validation rules as JSON.

Request:

```json
{
  "markup": "<!doctype html><html><head><title>Example</title></head><body><h1>Hello</h1></body></html>",
  "rules": [
    "Page must have a visible phone number",
    "Page must have a clear call to action"
  ]
}
```

Example with `curl`:

```bash
curl -X POST http://localhost:3000/audit \
  -H 'Content-Type: application/json' \
  --data-binary @- <<'JSON'
{
  "markup": "<!doctype html><html><head><title>Example</title></head><body><h1>Hello</h1></body></html>",
  "rules": [
    "Page must have a visible phone number",
    "Page must have a clear call to action"
  ]
}
JSON
```

The response has content type `text/html` and contains a complete validation report with:

- SEO findings from Lighthouse
- Accessibility findings from Lighthouse
- Results for each custom validation rule
- An overall summary generated by the LLM

The request body must contain a non-empty string `markup` and a non-empty array of strings called `rules`. Invalid requests receive HTTP `400`. Errors during Lighthouse or LLM processing receive HTTP `500` with an HTML error page.

## Audit flow

1. The submitted markup is written to a temporary local HTML file and served over a temporary HTTP server.
2. Puppeteer launches headless Chrome and Lighthouse audits the page.
3. Only SEO and accessibility Lighthouse categories are collected.
4. Failed Lighthouse audits, the original markup, and custom rules are sent to the configured LLM.
5. The LLM response is parsed as structured JSON.
6. The server renders the result as a self-contained HTML report.
7. Temporary files, the local HTTP server, and the browser are cleaned up.

When `ENVIRONMENT=development`, the failed Lighthouse findings for each request are also saved as JSON under `reports/`. These generated files are ignored by Git.

## Troubleshooting

### Puppeteer cannot launch Chrome

Make sure the machine has a compatible Chrome or Chromium installation and that the process is allowed to launch a headless browser. The server includes `--no-sandbox` and `--disable-dev-shm-usage` launch arguments for common server environments.

### The LLM request fails

Check that `LLM_BASE_URL`, `LLM_API_KEY`, and `LLM_MODEL` match the configured provider. The endpoint must support OpenAI-compatible chat completions and structured JSON responses.

### The server is using the wrong port

Set `PORT` in `.env`, for example:

```env
PORT=4000
```
